# Compact Proof Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the completed proof page compact and understandable while preserving all proof and verification behavior.

**Architecture:** Keep the existing proof data flow unchanged. Limit production changes to the proof page, its action component, and proof-specific CSS; verify the user-visible contract with the existing Playwright approval flow and focused component copy checks.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript 6, Vitest 4, Playwright 1.62.

## Global Constraints

- Remove only the two contextual **Verify proof** links; keep the global navigation entry.
- Use **Timestamped documents** in place of **Exact revisions in this proof**.
- Show the approval explanation as two sentence lines.
- Show “Checking whether OpenTimestamps has confirmed the digital fingerprints of both PDFs…” while confirmation is running.
- Do not change proof creation, PDF bytes, SHA-256 values, `.ots` files, or package contents.
- Add no dependencies.

- [ ] **Step 4: Implement the minimal action change**

Remove the `Link` import and contextual Verify link from `ProofStatus`. Start `check()` with the progress sentence:

```tsx
async function check() {
  setChecking(true);
  setMessage(
    "Checking whether OpenTimestamps has confirmed the digital fingerprints of both PDFs…",
  );
  try {
    const response = await fetch(`/api/projects/${projectId}/proof/check`, {
      method: "POST",
    });
    const body = await response.json();
    if (!response.ok) {
      setMessage(body.message ?? "The proofs could not be checked.");
      return;
    }
    setMessage(
      body.status === "confirmed"
        ? "Both proofs are confirmed."
        : body.status === "pending"
          ? "Confirmation is still pending. Check again later."
          : "The proof needs attention.",
    );
    router.refresh();
  } catch {
    setMessage("IdeaProof could not reach its local server. Try again.");
  } finally {
    setChecking(false);
  }
}
```

Keep the existing `role="status"` output so assistive technology receives both the progress and final result.
